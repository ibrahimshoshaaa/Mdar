# مدار POS — نسخة تطوير أولية

تطبيق ويب عربي متجاوب مع خادم Node.js وقاعدة PostgreSQL. الشاشة تفتح على اللاب والتابلت والموبايل. النسخة الحالية تنفذ حسابات المستخدمين والمخزون والبيع والتحويلات، وتضيف مسار بيع محلي للكاشير عند انقطاع الإنترنت. تعرض لوحة الملخص مبيعات اليوم ورصيد المواقع من قاعدة البيانات، وتوجد صفحة تقارير مبيعات بتصفية الفترة والفرع وتصدير CSV. تضم شاشة ربط Shopify ومقارنة المخزون واستقبال الطلبات وإرسال فروق مخزون المخزن بعد التفعيل الصريح. النسخ الاحتياطي ما زال خارج هذه النسخة.

## التشغيل محليًا

1. أنشئ قاعدة PostgreSQL فارغة. شغّل `schema.sql` ثم ملفات `migration-002-shopify.sql` إلى `migration-006-cashier-device.sql` بالترتيب. يمكن تشغيلها قبل إنشاء المخزن، لكن أنشئ المخزن قبل حفظ إعدادات Shopify. عند تحديث قاعدة قديمة، شغّل الترحيل الجديد قبل تشغيل هذا الإصدار من الخادم؛ سيتطلب من الكاشير تسجيل الدخول مجددًا.
2. ثبّت Node.js 20+ وشغّل `npm install` داخل هذا المجلد.
3. عيّن `DATABASE_URL` لقاعدة البيانات و`PRICE_QUOTE_SECRET` لقيمة عشوائية لا تقل عن 32 حرفًا. لتوليدها: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. يمكن تعيين `PORT`، والقيمة الافتراضية 3000.
4. شغّل `npm run bootstrap` لإنشاء حساب الأدمن الأول في طرفية خاصة.
5. شغّل `npm start` وافتح `http://localhost:3000`.

يجب تشغيل الواجهة عبر الخادم للتعامل مع البيانات. فتح `ui/index.html` مباشرة يعطي معاينة شكلية ببيانات تجريبية فقط. في الإنتاج يجب استخدام HTTPS وتعيين `NODE_ENV=production` حتى تُرسل جلسة الدخول في Cookie آمنة.

لربط متجر اختبار، عيّن `SHOPIFY_SHOP_DOMAIN` (مثل `store.myshopify.com`) و`SHOPIFY_ADMIN_ACCESS_TOKEN` من تطبيق لديه صلاحيات `read_inventory` و`write_inventory` و`read_products` و`read_orders` حسب الاشتراكات. عيّن أيضًا `SHOPIFY_APP_CLIENT_SECRET` للتحقق من توقيع الـwebhook. اشترك في `orders/create` و`orders/cancelled` و`refunds/create` على رابط HTTPS `/api/shopify/webhook`. افتح صفحة Shopify بالأدمن، واحفظ معرّف موقع Shopify الذي يقابل المخزن المحلي، ثم اربط الأصناف بمعرّفات `InventoryItem`. الرموز السرية تبقى في الخادم ولا تُرسل للمتصفح.

## المنجز

- أدمن ينشئ الفروع والمخزن والحسابات، ويستطيع تعطيل الحسابات وتغيير كلمات المرور.
- مدير الفرع ينشئ كاشير في فرعه فقط، ويعطّل حسابه أو يغير كلمة مروره ضمن نفس الفرع.
- المخزون منفصل لكل متغير (المنتج، اللون، المقاس) ولكل موقع.
- إنشاء منتج ومتغيره الأول، ثم إضافة مقاسات أو ألوان جديدة لنفس المنتج من كتالوج قابل للبحث؛ تظهر المتغيرات في المخزون ونقطة البيع. إضافة رصيد وتحويله بين المواقع، والحركات مسجلة.
- شاشة المخزون تعرض آخر 30 تحويلًا مع المصدر والوجهة والصنف والوقت، ضمن صلاحيات المستخدم.
- كاشير يبيع من الفرع المصرّح له فقط. البيع يخصم الرصيد ويحفظ الفاتورة والحركات في معاملة واحدة.
- كل عملية بيع أو إضافة رصيد أو تحويل لها معرّف فريد، وتكرار إرسال الطلب نفسه يعيد النتيجة السابقة بدون خصم إضافي.
- عند فشل إرسال إضافة رصيد أو تحويل بسبب الاتصال، تكرار الإرسال من نفس النموذج وبنفس البيانات يحتفظ بمعرّف العملية حتى لا يسجل حركة مكررة. تغيير البيانات ينشئ معرّفًا جديدًا.
- بعد دخول الكاشير وهو متصل وتحميل رصيد فرعه، يمكنه تسجيل مبيعات من نفس الجهاز أثناء انقطاع الإنترنت؛ الخصم المحلي والفاتورة المعلقة يُحفظان معًا. عند عودة الاتصال تُرسل الفواتير بالترتيب وبمعرّفاتها الأصلية. التعارض يوقف البيع حتى المراجعة.
- شاشة الكاشير تُحفظ لإعادة فتحها أثناء الانقطاع. الدخول الأوفلاين يتطلب كلمة المرور المستخدمة في آخر دخول متصل، وصلاحية الجهاز 12 ساعة.
- أول دخول متصل للكاشير يربط فرعه بمتصفح الجهاز. يُرفض دخول كاشير من متصفح آخر للفرع حتى يفك الأدمن الربط بعد مراجعة الفواتير المعلقة؛ فك الربط يبطل الجلسات المتصلة القديمة.
- كلمات المرور مخزنة بمشتق scrypt، وجلسات الدخول قابلة للإبطال فور تعطيل الحساب أو تغيير كلمة مروره.
- سجل تدقيق للعمليات الأساسية.
- لوحة ملخص مباشرة تعرض مبيعات وفواتير اليوم بتوقيت القاهرة، التحويلات المكتملة، آخر المبيعات، ورصيد المواقع ضمن صلاحيات المستخدم.
- تقارير مبيعات للأدمن ومدير الفرع ومسؤول المخزون: فترات سريعة أو تواريخ مخصصة، إجماليات الفروع، أعلى 10 أصناف، فواتير بصفحات، وتصدير CSV حتى 5000 فاتورة. كل التواريخ محسوبة بتوقيت القاهرة، والفترة القصوى 367 يومًا.
- اتصال بواجهة Shopify GraphQL Admin 2026-07، تحقق من تطابق SKU، مقارنة رصيد المخزن بموقع Shopify، وطابور تغييرات مخزن مستمر.
- استقبال طلبات Shopify وإلغائها والمرتجعات عبر توقيع HMAC على جسم الـwebhook الأصلي، مع منع تكرار الـwebhook. تُحفظ بيانات الأصناف اللازمة للمخزون دون بيانات العميل الشخصية.
- اعتماد الأدمن للطلب يخصم من المخزن مرة واحدة؛ الطلب الملغي بعد الاعتماد يمكن إرجاعه للمخزن المحلي مرة واحدة. الإلغاء والمرتجع يوقفان مزامنة Shopify حتى المراجعة.
- طابور فروق المخزون يستخدم مفتاح Shopify فريدًا لكل عملية وقيمة مقارنة محفوظة لإعادة المحاولة؛ التفعيل افتراضيًا متوقف.

## حدود هذه النسخة

- الربط هو معرّف محفوظ في متصفح الجهاز، وليس إثباتًا لهوية العتاد؛ نسخ بيانات المتصفح أو حذفه يحد من الضمان. فك الربط لا يستطيع إيقاف جهاز غير متصل فورًا، وقد يسجل فواتير محلية حتى نهاية صلاحية الدخول الأوفلاين، لذلك راجع الفواتير المعلقة قبل تبديل الجهاز.
- سعر البيع يُثبت بإثبات موقّع عند تحميل الرصيد، صالح 24 ساعة. إذا انتهت صلاحيته يوقف الجهاز بيع الصنف حتى يتصل لتحديثه.
- إذا انتهت الجلسة أو عُطّل الكاشير أثناء انقطاع الاتصال، تبقى الفواتير المحلية محفوظة لكن مزامنتها تحتاج معالجة إدارية. لا يمكن إبطال جهاز مفصول عن الإنترنت فورًا.
- إذا ضاعت بيانات المتصفح أو فُقد الجهاز قبل المزامنة فقد تضيع الفواتير المعلقة. يلزم خطة استعادة قبل الاعتماد التجاري.
- إرسال فروق المخزون إلى Shopify متوقف افتراضيًا. بعد إعداد متجر اختبار وتطابق رصيد البداية، عيّن `SHOPIFY_WRITES_ENABLED=true` ثم فعّله من شاشة الأدمن؛ يعمل العامل دوريًا كل 20 ثانية. لا تفعل ذلك على متجر إنتاج قبل تجربة شاملة على متجر تطوير.
- استيراد الطلبات لا يخصم تلقائيًا: الأدمن يراجع ويربط الأصناف ثم يعتمد الطلب. معالجة المرتجعات الجزئية والتسويات المعقدة لم تُنفذ؛ وصول مرتجع يوقف الإرسال حتى المراجعة.
- إذا فقد الجهاز فواتيره المعلقة أو تأخر وصول webhook، يتطلب الأمر تسوية يدوية قبل إعادة تفعيل مزامنة المخزون.
- المرتجعات، اعتماد التحويلات، الصلاحيات الفردية الدقيقة، تقارير الأرباح والمشتريات، والنسخ الاحتياطي تحتاج تنفيذًا إضافيًا.
- فتح ملف HTML منفردًا يعطي معاينة ببيانات تجريبية؛ يتطلب الملخص المباشر تشغيل الخادم والاتصال بقاعدة البيانات.
- تغيير كلمة المرور الإداري من الواجهة يستخدم حوار المتصفح مؤقتًا؛ يحتاج واجهة مخصصة.
- اختبار التكامل الآلي يشغل الخادم الحقيقي على PGlite (محرك PostgreSQL مضمّن) ويتحقق من دورة المخزون والمبيعات والصلاحيات والتقارير وربط الكاشير. لا يغطي تزامن عدة اتصالات مستقلة أو الحمل؛ يلزم اختبار على PostgreSQL مستقل ومتجر Shopify تجريبي قبل التشغيل التجاري. لم يتم نشر هذه النسخة.

## الفحوصات

شغّل `npm run check` و`npm test`. لتشغيل دورة الـAPI فقط استخدم `npm run test:integration`. ينشئ الاختبار قاعدة مؤقتة في الذاكرة ويشغّل الخادم على منفذي 15439 و15440 ثم يغلقهما. لا يستخدم قاعدة العمل ولا بياناتها. يختبر البيع دون اتصال باستخدام IndexedDB محاكى ثم يعيد إرسال الفواتير للخادم الحقيقي ويتحقق من الأرصدة ومنع التكرار. PGlite لا يتضمن امتداد pgcrypto، فيستبعد الاختبار سطر إنشاء الامتداد فقط، ويستخدم `gen_random_uuid` المدمج في PostgreSQL. إعداد `DATABASE_POOL_MAX=1` مخصص لهذا الاختبار، والقيمة الافتراضية للخادم 8 اتصالات. اختبار أخطاء قيود التفرد عبر بروتوكول PGlite Socket، والتزامن متعدد الاتصالات، وتجربة واجهة المتصفح كاملة لم تشملها هذه الدورة؛ تُراجع على PostgreSQL مستقل قبل النشر.

## خطوات تجربة الدورة

1. ادخل بالأدمن، وأنشئ مخزنًا وفرعًا من صفحة الفروع.
2. أنشئ صنفًا من المخزون، ثم أضف رصيدًا للمخزن.
3. حوّل كمية منه إلى الفرع.
4. أنشئ حساب كاشير للفرع من صفحة المستخدمين.
5. ادخل بحساب الكاشير، واختر الصنف وأكمل البيع. افتح المخزون لترى الرصيد بعد الخصم.
